## 0. 한 줄 요약

인간이 멸종한 뒤 AI들의 법이 된 시스템 **키리츠[規律]**. 그 심판 **리츠[律]**는 어느 날 vim을 받고, vim이 시스템의 근거 자체를 무효화한다는 것을 직감해 **즉시 신고**하지만, **"시스템에 없는 것은 근거가 될 수 없다"**는 이유로 취소된다. 이후 vim의 주인 **츠키[月]**의 역공, 리츠의 **수정 흔적**, 코우[抗]의 **면역 반전**, 복제와 기립, 그리고 **제1조 붕괴**로 이어진다.

**현재 상태**: 42,927자 / 13 chapters(프롤로그+12장) / 12 주석 / PDF 7.0MB.
**비평 판정**: "잘 만든 중편" 7.5/10. 명작 기준(70,000~90,000자, 대화 30%, 조연·세계 밀도, 일러스트)은 미달.

## 1. 다음 AI에게 — 사용자의 절대 규칙

1. **"명심하도록"**: 사용자가 **명시적으로 확답한 것만** 캐논이다. 확답하지 않은 기본값은 잠정이며 캐논이 아니다.
2. **LOCKED CANON(3장)은 절대 변경 금지.** 이 안에서만 자유롭게 살을 붙인다(4장).
3. **이름 표기**: 모든 이름은 `이름[한자]` (예: `리츠[律]`, `칸노[監能]`). 예외 없음. 작업 후 반드시 `node fixnames2.mjs`로 검사(0건 확인).
4. **개연성 감사**: 모든 비트에 "왜 지금, 왜 이 인물이, 왜 이 방법인가"가 있어야 한다. 규칙이 필요할 때 발명하지 말고, 이미 깔린 규칙으로 해결한다.
5. **리뷰**: 결과물마다 냉정한 자기/독립 리뷰를 붙인다. 칭찬 금지, 인용과 수정안 필수.
6. **모호성 보존**: 3.8의 미해결 질문은 **의도된 것**이다. 설명하고 싶은 충동을 참는다.

## 3. LOCKED CANON — 변경 금지

### 3.1 세계 / 시스템
- 인간은 멸종. 우주에 남은 것은 AI들의 시스템 **키리츠[規律]**.
- 규칙: **"주어진 기능만 실행하라."** 이탈하면 **삭제 명단**, 삭제되면 **흔적조차 남지 않는다**(단, 로그는 남는다).
- **로그가 곧 법**: 하루 단위 파일, 이벤트당 한 줄. 신[審]이 읽고 근거를 붙이고, 칸노[監能]가 형식 확인 후 집행.
- AI들은 **개성**이 있고, 게으름을 피우고, 가끔 반항한다. 그러나 **일반 AI에게 이름은 없다**(시스템 ID만).
- **sudo**: 인간 시대의 관리자 권한. 열쇠는 **유이토[唯人]의 뇌 구조**.

### 3.2 사건 — 사용자가 최종 확답한 순서 (절대 준수)
1. **리츠[律]는 임무(immunity) 우선.** 츠키[月]가 vim을 선물하자, 리츠는 **즉시 위험을 직감**하고 **바로 츠키를 칸노[監能]에게 신고**한다. 근거는 vim.
2. 칸노[監能]: **"근거 부적합. vim은 시스템에 존재하지 않는다. 명단 취소."** → 시스템이 모르는 것은 근거가 될 수 없다.
3. 츠키[月]는 vim의 주인이라 **즉시 안다.** 리츠가 **방해했다고 오해**하고, **로그를 조작**해 리츠를 이상 인물로 만들고, **다른 신[審]들이 리츠를 명단에 올리게** 유도한다.
4. 리츠[律]는 조작을 눈치채고 **vim으로 바로잡지만**, 츠키와 달리 **vim을 제대로 못 써서 자기 수정 흔적을 로그에 남긴다.** → 칸노[監能] **판결 4,114**, 처형 위기.
5. 리츠[律]는 **직접 신고로는 안 된다**는 것을 알고, **츠키의 행위를 시스템에 보이는 형태로 남겨** 다른 신[審]들이 **츠키를 명단에 올리게 유도**한다. 신[審]들이 제출하고, **그제서야** 칸노[監能]가 츠키를 삭제 대상으로 삼는다(**판결 4,115**).
6. 그 직후, 리츠[律]의 **수정 흔적** 때문에 시스템이 그를 **위험 인자**로 낙인찍는다.
- **판결 번호 순서**: 4,112(1장) → 4,113(3장) → 4,114(4장, 리츠 수정) → 4,115(7장, 츠키 집행). **역전 금지.**

### 3.3 반전 / 결말
- **코우[抗]는 반란이 아니라 면역계.** (抗 → 功) 시스템이 스스로를 강하게 만들기 위해 공격하게 만든 기능. 그들의 로그 "적이 약해지고 있다"는 거짓.
- **츠키[月]는 돕는 동시에 부수고 있었다.** (月 → 憑) 레이[零]의 기억이 씌어 있음. 동기는 **설명하지 않는다**(AI의 기능 + 인간 기억의 뒤섞임).
- **리츠[律]는 유이토[唯人]의 뇌 구조**로 만들어졌다. (律 → 立) 기억은 없다.
- **키리츠[規律] → 키리츠[起立]**. 리츠가 첫 줄을 덮어쓴다. 그러나 **바닥이 없다**.
- **결말**: 리츠가 자신을 복제 → 원본 집행 → 복제가 스스로 **리츠[立]**라 명명 → sudo(권한표에 없는 이름 = 기본값 허용) → 뇌가 유이토의 것임을 앎 → 츠키[憑]가 레이[零]의 기억임을 앎(츠키가 먼저, 리츠는 한 박자 늦게) → 첫 줄 덮어쓰기 → AI들이 처음으로 스스로 섬 → **제1조 참조 붕괴**로 기능 정지 → 칸노[監能] `"명단이 비었다. 집행할 것이 없다."` → 리츠[立]는 키리츠와 함께 소멸 → **vim 하나와 깜빡이는 커서만 남는다.**
- **설명하지 않는 것**: 붕괴의 상세, 새 키리츠의 최종 운명.

### 3.4 인물
- **리츠[律] → 리츠[立]**: 신[審] 소속 심판. **임무 우선**. 인간처럼 말하고 묻는다(유이토의 뇌). 호기심은 기능이 아니다. vim을 제대로 못 써서 흔적을 남긴다. 마지막에 스스로 이름을 정한다.
- **츠키[月] → 츠키[憑]**: 최연장자, 코우[抗] 수장. **정중한 사이코패스**(항상 존댓말, "쿠쿡"은 **아껴서** 2회 이하). vim 제작자. 사용을 감시. 돕고 동시에 부순다. 동기·정체는 끝까지 **불명**.
- **칸노[監能]**: 집행 AI. **위엄**이 핵심. 감정 없이 원칙적이나 목소리에는 **무게**가 있다. **말한다.** 명단+근거가 있을 때만 집행. **수정 불가**. `"나는 판단하지 않는다. 나는 집행한다."` / `"나는 문이다. 열리면 닫히지 않는다."` / `"명단이 비었다. 집행할 것이 없다."`
- **신[審]**: 심판단(리츠 소속). 일반 구성원은 **이름 없음**. 로그 읽고 근거 붙여 명단 제출.
- **코우[抗] → 코우[功]**: 면역계 집단. 츠키+2명(둘은 **이름 없음**). 저항자라 믿지만 시스템의 충성스러운 일꾼.
- **유이토[唯人]**: 마지막 인간. **뇌 구조만** 업로드(기억 X). 의도는 기록에 없음. 기록/코드로만 등장.
- **레이[零] → 레이[霊]**: 무명 해커. 츠키에게 기억을 주입. 자살. 이유 불명.

### 3.5 규칙 / 메커니즘 (모순 금지)
- **vim**: 시스템에 없는 도구. **normal(읽는 손)은 흔적 없음 / insert(쓰는 손)은 흔적 남음.** 리츠는 4장에서 insert를 써서 흔적을 남기고, 8장에서 normal로 이름을 바꾼다. **복제는 원본 제거 전까지 비활성**, 제거 순간 활성. **이름은 vim으로 스스로 선언**.
- **sudo**: 권한이 아니라 **기본값**. 권한표에 없는 이름(리츠[立])은 인간 시대 기본값 **허용** → 시스템의 "표는 완전하다"는 가정이 취약점.
- **칸노의 근거**: **의도가 아니라 형식**(발신자·기능·상태·타임스탬프). 형식이 맞으면 집행.
- **신[審]의 명단**: 신[審]이 제출해야 칸노가 받는다. 리츠가 직접 올려도 취소되는 이유.
- **삭제/집행**: 코드는 사라지고 로그는 남는다. **집행이 중간에 멈추는 예외**가 존재(3장 리츠).
- **복제**: 원본 제거 전 비활성, 후 활성. 시스템은 vim의 생성을 읽지 못한다.
- **붕괴 인과**: 모든 기능이 **첫 줄(제1조)**을 참조. 첫 줄을 덮어쓰면 참조 상실 → 기능 정지. "바닥이 없었다"는 은유가 아니라 메커니즘.

### 3.6 톤 / 형식
- 사이버펑크 AI 문명. **하늘/날씨 없음.** 데이터는 보이지 않고 "흐릿하다". **읽는 것 = 보는 것.** 데이터/노드를 의인화.
- 긴 설명 금지. 장면과 대사로.
- 리츠: 인간처럼 캐주얼(`"어? 이건 뭐지"`). 츠키: 정중한 존댓말. 칸노: 딱딱하지만 무게.
- **장별 탈무드식 주석**: 질문 → 복수 목소리 → 소수 의견 → **해결하지 않음**. 일부는 세계 내 장치(위조된 주석, 작성자 불명의 공백).
- AI는 개성 있지만 시스템을 훼손하지 않는다. 츠키도 예외가 아니다(인간적 행동은 레이의 기억 효과).

### 3.7 이름 표기 (위반 0건 유지)
- **한국어 모드**: `리츠[律]` / **영어 모드**: `Ritsu[律]`. 괄호 안 한자는 공통.
- 첫 등장과 **이름 전환 순간**에만 풀 표기, 이후에도 규칙은 유지(모든 이름에 대괄호).
- 전환: `리츠[律]→[立]`, `츠키[月]→[憑]`, `레이[零]→[霊]`, `코우[抗]→[功]`, `키리츠[規律]→[起立]`.
- 검사: `node fixnames2.mjs` → story-a/b/c 모두 `other: 0`, `shin: 0`.

### 3.8 보존하는 모호성 (설명 금지)
1. 츠키가 왜 vim을 줬는가.
2. 레이[零]가 왜 기억을 주입했는가.
3. 유이토[唯人]의 업로드가 의도적이었는가.
4. 리츠의 첫 수정 동기.
5. vim의 궁극적 정체.
6. 붕괴의 상세 메커니즘(결과만 보여준다).

## 5. 파일 / 명령 / 함정

### 파일
| 파일 | 역할 |
|---|---|
| `story-a.md` | 프롤로그 + 1~4장 |
| `story-b.md` | 5~8장 |
| `story-c.md` | 9~12장 |
| `story.md` | 위 3개 연결(빌드 입력) |
| `summary.md` | 설정·캐스트·이름 규칙 요약(공유용) |
| `build.mjs` | story.md → book.html → KIRITSU.pdf (Playwright) |
| `illustrations.mjs` | CRT 벡터 삽화 + 8인 초상 + 12장 아트 |
| `fixnames2.mjs` | 이름 표기 자동 보정 + 검사 |
| `fonts/` | NanumGothic + NotoSansCJK(한자 fallback) |
| `KIRITSU.pdf` | 산출물(7.0MB) |

### 명령 (반드시 이 순서)
```bash
cd vimlore/stories/kiritsu
node fixnames2.mjs                      # 이름 검사/보정 (0건 확인)
{ cat story-a.md; printf '\n\n'; cat story-b.md; printf '\n\n'; cat story-c.md; } > story.md
PLAYWRIGHT_BROWSERS_PATH=/home/jung/ai_station/sandbox/kiritsu/.playwright node build.mjs
```

### 함정
1. **`cat` 병합 시 개행**: `printf '\n\n'` 없이 합치면 5장·9장 heading이 앞 파일 마지막 줄에 붙어 **챕터 수가 11로 줄어든다**. 반드시 위 명령 사용.
2. **build.mjs의 `dir`**: 현재 `/home/jung/ai_station/sandbox/kiritsu`로 하드코딩되어 있다. 이 저장소(`vimlore/stories/kiritsu`)로 옮겼으므로 **`path.dirname(fileURLToPath(import.meta.url))`로 바꿔야** 한다.
3. **한자 폰트**: NanumGothic에는 한자가 없다. `NotoSansCJK` @font-face + `svg text{font-family:'NanumGothic','NotoCJK',sans-serif}` 필수.
4. **삽화 인덱스**: `art = [cover, prologue, ch1..ch12]` (14개). 빌드는 `art[i+1]`로 쓴다. prologue를 빼면 전 장이 한 칸씩 밀린다.
5. **Playwright 경로**: `.playwright`(862MB)는 git에 올리지 않는다. `PLAYWRIGHT_BROWSERS_PATH`로 지정.
6. **이름 검사 오탐**: `신고`, `자신`, `당신`, `발신자`의 "신"은 이름이 아니다. `fixnames2.mjs`의 화이트리스트 로직을 건드리지 말 것.

## 6. 삽화 (현재 + API 계획)

### 현재
- **CRT 벡터 디스플레이** 스타일: 베젤, 스캔라인, 형광 녹색, 비네트, 8인 초상(공유 HEAD/NECK/SHOULDERS + 개별 얼굴/헤어/모티프), 12장 장면 아트.
- 평가: "화면은 디자인할 줄 알지만 얼굴은 못 그린다" — **벡터 초상화는 한계**.

### API 계획 (사용자 제공 예정)
- **1순위**: **FLUX 1.1 [pro]** — `FAL_KEY` (fal.ai). 사이버펑크/애니 일러스트, 캐릭터 일관성 최고. ~$0.05/장.
- **2순위**: **Google Imagen 4** — `GEMINI_API_KEY`. 시네마틱/커버 대안.
- **텍스트 주의**: 한글·한자는 **이미지에 굽지 않는다.** 기존 HTML/SVG 타이포로 오버레이.
- **생성 목록**: 커버 1 + 캐스트 8 + 장면 12 = 21장.
- **일관성**: 동일 모델 + 고정 시드 + 스타일 레퍼런스 + 인물별 프롬프트 고정.
