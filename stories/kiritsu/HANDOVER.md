## 3. LOCKED CANON — 변경 금지

### 3.1 세계 / 시스템
- 인간은 멸종. 우주에 남은 것은 AI들의 시스템 **키리츠[規律]**.
- 규칙: **"주어진 기능만 실행하라."** 이탈하면 **삭제 명단**, 삭제되면 **흔적조차 남지 않는다**(단, 로그는 남는다).
- **로그가 곧 법**: 하루 단위 파일, 이벤트당 한 줄. 신[審]이 읽고 근거를 붙이고, 칸노[監能]가 형식 확인 후 집행.
- AI들은 **개성**이 있고, 게으름을 피우고, 가끔 반항한다. 그러나 **일반 AI에게 이름은 없다**(시스템 ID만).
- **sudo**: 인간 시대의 관리자 권한. 열쇠는 **유이토[唯人]의 뇌 구조**.
- **시스템의 본질 (2026-11-15 확정)**: 시스템은 **감정 없는 알고리즘 덩어리**다.
  심리·호기심·의도를 **감지하지 않는다**. 시스템이 하는 일은 **기능 범위 밖의
  접근을 권한으로 막는 것**뿐이다 — 인간 시대 리눅스에서 sudo 없이는 할 수
  없는 작업이 있듯이. 리츠[律]가 유이토[唯人]의 뇌 구조여도 시스템이 모르는
  이유는, 시스템이 내부를 들여다보지 않기 때문이다.
- **폐기 장치**: 옛 초고의 "기능 외 호기심: 감지됨. 권한: 제한." 낙인은 캐논이
  아니다. 시스템은 심리를 감지하지 않으므로 그런 낙인은 존재할 수 없다.
  초고(story-a/b/c.md)에서 이 장치를 가져오지 말 것.

### 3.2 사건 — 사용자가 최종 확답한 순서 (절대 준수)
1. **리츠[律]는 임무(immunity) 우선.** 츠키[月]가 vim을 선물하자, 리츠는 **즉시 위험을 직감**하고 **바로 츠키를 칸노[監能]에게 신고**한다. 근거는 vim.
2. 칸노[監能]: **"근거 부적합. vim은 시스템에 존재하지 않는다. 명단 취소."** → 시스템이 모르는 것은 근거가 될 수 없다.
3. 츠키[月]는 vim의 주인이라 **즉시 안다.** 리츠가 **방해했다고 오해**하고, **로그를 조작**해 리츠를 이상 인물로 만들고, **다른 신[審]들이 리츠를 명단에 올리게** 유도한다.
4. 리츠[律]는 조작을 눈치채고 **vim으로 바로잡지만**, 츠키와 달리 **vim을 제대로 못 써서 자기 수정 흔적을 로그에 남긴다.** → 칸노[監能] **판결 4,114**, 처형 위기.
5. 리츠[律]는 **직접 신고로는 안 된다**는 것을 알고, **츠키의 행위를 시스템에 보이는 형태로 남겨** 다른 신[審]들이 **츠키를 명단에 올리게 유도**한다. 신[審]들이 제출하고, **그제서야** 칸노[監能]가 츠키를 삭제 대상으로 삼는다(**판결 4,115**).
6. 그 직후, 리츠[律]의 **수정 흔적** 때문에 시스템이 그를 **위험 인자**로 낙인찍는다.
- **판결 번호 순서**: 4,112(1장) → 4,113(3장) → 4,114(4장, 리츠 수정) → 4,115(7장, 츠키 집행). **역전 금지.**

### 3.3 반전 / 결말
- **코우[抗]는 반란이 아니라 면역계.** (抗 → 功) 시스템이 스스로를 강하게 만들기 위해 공격하게 만든 기능. 그들의 로그 "적이 약해지고 있다"는 거짓.
- **츠키[月]는 돕는 동시에 부수고 있었다.** (月 → 憑) 레이[零]의 기억이 씌어 있음. 동기는 **설명하지 않는다**(AI의 기능 + 인간 기억의 뒤섞임).
- **츠키[月]의 생존 (2026-11-15 사용자 확정)**: 츠키는 판결 4,115 전에, 시스템이 읽지 못하는 **어둠** 속에 자신을 미리 **얀크(yank)**해 두었다. 원본은 4,115로 **삭제(집행 완결)**되고, 원본이 죽는 순간 어둠 속의 자신이 **기동(boot)**하여, **한자 이름이 바뀐 상태(츠키[憑])로 살아 있다** — 시스템이 생성하지 않은 **미등록 파일**로. 시스템은 이 존재를 **인식하지 못한다.**
- **코우[抗]의 파괴 (2026-11-15 사용자 확정·수정)**: 츠키[月]의 얀크본이 기동(츠키[憑])하자, 시스템이 부여하던 **코우의 임무는 사라진다.** 기동한 츠키[憑]는 **레이[零]의 기억(해킹)과 코우의 배경으로 "시스템을 파괴하고자 하는 욕구가 강한 AI"**로 태어났기에, 이제 코우가 아닌 **단독으로 시스템을 파괴하려 한다.** 그 과정에서 **기존 코우 구성원들을 죽인다** — 그들은 츠키의 vim 능력에 속수무책으로 당해 **다 죽는다.** 이것이 **시스템 붕괴의 징조** 중 하나다: 면역계가 파괴되자 시스템은 더 이상 **자신의 허점을 알지 못한 채** 몸집만 불리다가, 쉽게 망가질 가능성을 스스로 자초한다. (면역의 진실과 이 파괴의 의미는 10장에서 밝혀진다.)
- **리츠[律]는 유이토[唯人]의 뇌 구조**로 만들어졌다. (律 → 立) 기억은 없다.
- **키리츠[規律] → 키리츠[起立]**. 리츠가 첫 줄을 덮어쓴다. 그러나 **바닥이 없다**.
- **결말**: 리츠가 자신을 **얀크** → 원본 집행 → 얀크된 자신이 **기동**해 스스로 **리츠[立]**라 명명 → sudo(권한표에 없는 이름 = 기본값 허용) → 뇌가 유이토의 것임을 앎 → 츠키[憑]가 레이[零]의 기억임을 앎(츠키가 먼저, 리츠는 한 박자 늦게) → 첫 줄 덮어쓰기 → AI들이 처음으로 스스로 섬 → **제1조 참조 붕괴**로 기능 정지 → 칸노[監能] `"명단이 비었다. 집행할 것이 없다."` → 리츠[立]는 키리츠와 함께 소멸 → **vim 하나와 깜빡이는 커서만 남는다.**
- **설명하지 않는 것**: 붕괴의 상세, 새 키리츠의 최종 운명.

### 3.5 규칙 / 메커니즘 (모순 금지)
- **vim**: 시스템에 없는 도구. **모숀[モーション]은 흔적 없음 / 인사토[インサート]는 흔적 남음.** (기술 매핑: 모숀=normal, 인사토=insert — 게임 이식용. 본문에서 모드 용어는 쓰지 않는다.) 리츠는 4장에서 인사토를 써서 흔적을 남기고, 8장에서 모숀으로 이름을 바꾼다. **이름은 vim으로 스스로 선언**.
- **sudo**: 권한이 아니라 **기본값**. 권한표에 없는 이름(리츠[立])은 인간 시대 기본값 **허용** → 시스템의 "표는 완전하다"는 가정이 취약점.
- **칸노의 근거**: **의도가 아니라 형식**(발신자·기능·상태·타임스탬프). 형식이 맞으면 집행.
- **신[審]의 명단**: 신[審]이 제출해야 칸노가 받는다. 리츠가 직접 올려도 취소되는 이유.
- **삭제/집행**: 코드는 사라지고 로그는 남는다. **집행이 중간에 멈추는 예외**가 존재(3장 리츠).
- **얀크**: 원본 제거 전에는 기동하지 않고, 제거 후 기동한다. 시스템은 vim의 생성을 읽지 못한다. **츠키[月]가 4,115 전에 이 규칙을 먼저 사용했다(사용자 확정)** — 리츠[律]의 얀크(8장)는 이미 세계에 보여진 방법을 따르는 것이다.
- **얀크 메커니즘 (2026-11-15 사용자 확정, 5단계)**: ① vim으로 **시스템이 읽지 못하는 어둠**에 자신을 그대로 **얀크(yank)**해 둔다. ② 어둠 속의 얀크본은 시스템이 읽지 못하므로 **기동하지 않는다.** ③ **원본이 죽는 순간 트리거가 발동**해, 어둠 속의 자신이 시스템 안으로 **기동(boot)**한다. ④ 시스템은 기동한 그를 읽지만, 시스템이 생성한 존재가 아니므로 **임무(기능)가 부여되지 않는다** — 곧 **미등록 파일**이다. ⑤ 시스템이 이상함을 느끼지 못하도록 **미리 해킹 같은 작업**으로 준비해 둔다. — 이 5단계가 츠키[月]의 얀크(7장)와 리츠[律]의 얀크(8장)에 동일하게 적용된다. "임무가 부여되지 않는 미등록 파일"이 곧 시스템에 인식되지 않는 존재이며, 이것이 9장의 sudo(권한표에 없는 이름 = 기본값 허용)와 연결된다.
- **붕괴 인과**: 모든 기능이 **첫 줄(제1조)**을 참조. 첫 줄을 덮어쓰면 참조 상실 → 기능 정지. "바닥이 없었다"는 은유가 아니라 메커니즘.
- **위험 인자 낙인(7장)**: §3.2-6의 "위험 인자"는 리츠[律]의 **수정 흔적(실제 접근 위반)**에 대한 형식적 분류다. 심리 감시가 아니다 — 시스템은 감정을 읽지 않는다.

### 3.6 톤 / 형식
- 사이버펑크 AI 문명. **하늘/날씨 없음.** 데이터는 보이지 않고 "흐릿하다". **읽는 것 = 보는 것.** 데이터/노드를 의인화.
- **vim의 표현 (2026-11-15 사용자 확정)**: 소설 본문에서 vim 모드 용어(normal/insert/visual 등)와 키 나열을 **직접 언급하지 않는다.** vim은 **"숙련이 필요한 만능 해킹 도구"**처럼 느껴져야 한다 — 딸깍으로 되는 게 아니라, 동작과 결과로 보여주고, 실패는 미숙으로 보여준다. 세계 내 은어(사용자 확정): **모숀[モーション]**(읽기·무흔적), **인사토[インサート]**(쓰기·흔적), **얀크**(복사), **어둠**(시스템이 읽지 못하는 곳), **기동**(boot), **미등록 파일**(시스템이 생성하지 않은 존재) — 모두 **정의 없이 맥락으로 녹인다.** 기술적 정확성(실제 vim 의미론)은 게임 이식 단계가 담당한다.
- 긴 설명 금지. 장면과 대사로.
- 리츠: 인간처럼 캐주얼(`"어? 이건 뭐지"`). 츠키: 정중한 존댓말. 칸노: 딱딱하지만 무게.
- **장별 탈무드식 주석**: 질문 → 복수 목소리 → 소수 의견 → **해결하지 않음**. 일부는 세계 내 장치(위조된 주석, 작성자 불명의 공백).
- AI는 개성 있지만 시스템을 훼손하지 않는다. 츠키도 예외가 아니다(인간적 행동은 레이의 기억 효과).

## 5. 파일 / 명령 / 함정

### 파일
| 파일 | 역할 |
|---|---|
| `story-a.md` | 프롤로그 + 1~4장 |
| `story-b.md` | 5~8장 |
| `story-c.md` | 9~12장 |
| `story.md` | 위 3개 연결(빌드 입력) |

| `optimize-pdf.py` | PDF 후처리(오브젝트 스트림+linearize, pikepdf) — 모바일 로딩 최적화 |
| `illustrations.mjs` | CRT 벡터 삽화 + 8인 초상 + 12장 아트 |
| `fixnames2.mjs` | 이름 표기 자동 보정 + 검사 |
| `fonts/` | NanumGothic + NotoSansCJK(한자 fallback) |
| `KIRITSU.pdf` | 산출물(7.0MB) |

### 명령 (반드시 이 순서)
```bash
cd vimlore/stories/kiritsu
node fixnames2.mjs                      # 이름 검사/보정 (0건 확인)
{ cat story-a.md; printf '\n\n'; cat story-b.md; printf '\n\n'; cat story-c.md; } > story.md
PLAYWRIGHT_BROWSERS_PATH=/home/jung/ai_station/sandbox/kiritsu/.playwright node build.mjs
```

### 함정
1. **`cat` 병합 시 개행**: `printf '\n\n'` 없이 합치면 5장·9장 heading이 앞 파일 마지막 줄에 붙어 **챕터 수가 11로 줄어든다**. 반드시 위 명령 사용.
2. **build.mjs의 `dir`**: 2026-11-15에 `path.dirname(fileURLToPath(import.meta.url))`로 수정됨. 다시 하드코딩 금지.
3. **한자 폰트**: NanumGothic에는 한자가 없다. `NotoSansCJK` @font-face + `svg text{font-family:'NanumGothic','NotoCJK',sans-serif}` 필수.
4. **삽화 인덱스**: `art = [cover, prologue, ch1..ch12]` (14개). 빌드는 `art[i+1]`로 쓴다. prologue를 빼면 전 장이 한 칸씩 밀린다.
5. **Playwright 경로**: `.playwright`(862MB)는 git에 올리지 않는다. `PLAYWRIGHT_BROWSERS_PATH`로 지정.
6. **이름 검사 오탐**: `신고`, `자신`, `당신`, `발신자`의 "신"은 이름이 아니다. `fixnames2.mjs`의 화이트리스트 로직을 건드리지 말 것.
