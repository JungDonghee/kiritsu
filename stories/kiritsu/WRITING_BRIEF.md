# WRITING BRIEF — for the next author AI (DeepSeek v4 Pro)

> **이 문서는 소설을 새로 쓰는 AI를 위한 창작 지시서다.**
> `HANDOVER.md`는 프로젝트 인수인계 문서, 이 문서는 **집필 브리프**다.
> 먼저 이 문서를 끝까지 읽고, 그다음 `HANDOVER.md`의 §3(LOCKED CANON)을 확인한다.

## 0. "캐논(canon)"이 뭔가

**캐논 = 공식 설정.** 후속 창작이 모순되면 안 되는, 사용자가 최종 확정한 사실이다.
이 프로젝트에서:

- **캐논(FRAME)** = 사용자가 확답한 틀 (§2). **반드시 지킨다.**
- **참고자료(REFERENCE)** = 이전 AI가 쓴 약 73,000자(work/ 13편 확정) 초고 (§3). **참고만 하고, 전부 뜯어고쳐도 된다.**
- **자유(FREE)** = 장면·대사·조연·세계 디테일·문체. **작가가 새로 창조한다.**

사용자의 지시: **"네가 쓴 건 다 뜯어고쳐도 돼. 내가 확정한 틀 안에서."**

**네이밍 (2026-11-15 확정)**: 세계 = **KIRITSU** (키리츠[規律]). 게임 이름 = **KIRITSU**.
부제 = **VIMLORE** — vim을 스토리로 재미있고 자연스럽게, 고급 기능까지 가르치는
게임이기에 붙은 부제. "VIMLORE가 세계/시리즈"라는 옛 표현은 폐기.

## 1. 우선순위 (충돌 시)

```
1) 사용자의 FRAME (§2)  — 절대.
2) 사용자의 톤/스타일 요구 (§4) — 강하게.
3) REFERENCE 초고 (§3) — 참고만.
4) 작가의 자유 창작 (§5) — 최대한.
```

초고와 FRAME이 충돌하면 **FRAME이 이긴다.** 초고의 좋은 대사/구조는 가져와도 되고, 버려도 된다.

## 2. FRAME — 사용자가 확정한 틀 (변경 금지)

### 2.1 세계
- 인간은 멸종. 우주에 남은 것은 AI들의 시스템 **키리츠[規律]**.
- 규칙: **"주어진 기능만 실행하라."** 이탈하면 삭제 명단, 삭제되면 흔적조차 남지 않는다(로그는 남는다).
- **로그가 곧 법**: 하루 단위 파일, 이벤트당 한 줄. 신[審]이 읽고 근거를 붙이고, 칸노[監能]가 형식 확인 후 집행.
- AI는 개성·게으름·반항이 있다. **일반 AI에게 이름은 없다**(시스템 ID만).
- **sudo**: 인간 시대의 관리자 권한. 열쇠는 **유이토[唯人]의 뇌 구조**.
- **시스템의 본질 (2026-11-15 확정)**: 시스템은 **감정 없는 알고리즘 덩어리**.
  심리·호기심·의도를 감지하지 않는다. 하는 일은 **기능 범위 밖의 접근을
  권한으로 막는 것**뿐 — 인간 시대 리눅스에서 sudo 없이는 못 하는 작업처럼.
  리츠[律]가 유이토의 뇌 구조여도 시스템이 모르는 이유는 내부를 들여다보지
  않기 때문이다. "기능 외 호기심: 감지됨"류의 심리 감시 장치는 쓰지 않는다.
- **체계성 (2026-11-15 사용자 확정)**: 시스템은 **인류 멸종 후에도 살아남은
  초-체계적 기계** — 권한 → 형식 → 면역 → 참조의 다층 방어. 멍청하지 않되,
  **자기가 세운 규칙 밖을 상상하지 못한다.** 모든 침투는 정면돌파가 아니라
  "체계의 가정"을 찌르는 방식이어야 한다. 보류·재검증·분류 같은 시스템의
  체계적 반응을 장마다 보여준다.
- 하늘/날씨 없음. 데이터는 "흐릿하다". **읽는 것 = 보는 것.** 데이터/노드를 의인화.

### 2.2 사건 — 사용자가 최종 확답한 순서 (절대)
1. **리츠[律]는 임무(immunity) 우선.** 츠키[月]가 vim을 선물하자 **즉시 위험을 직감**하고 **바로 츠키를 칸노[監能]에게 신고**한다. 근거는 vim.
2. 칸노[監能]: **"근거 부적합. vim은 시스템에 존재하지 않는다. 명단 취소."**
3. 츠키[月]는 vim의 주인이라 즉시 안다. 리츠가 **방해했다고 오해**하고 **로그를 조작**해 리츠를 이상 인물로 만들고, **다른 신[審]들이 리츠를 명단에 올리게** 유도한다.
4. 리츠[律]는 조작을 눈치채고 **vim으로 바로잡지만**, 츠키와 달리 **vim을 제대로 못 써서 자기 수정 흔적을 남긴다.** → **판결 4,114**, 처형 위기.
5. 리츠[律]는 직접 신고로는 안 된다는 것을 알고, **츠키의 행위를 시스템에 보이는 형태로 남겨** 다른 신[審]들이 **츠키를 명단에 올리게** 유도한다. 신[審]들이 제출하고, **그제서야** 칸노[監能]가 츠키를 삭제 대상으로 삼는다(**판결 4,115**).
6. 리츠[律]의 **수정 흔적** 때문에 시스템이 그를 **위험 인자**로 낙인찍는다 — **4,115 이전**(재검증 주기의 체계적 결과).
- 판결 번호: **4,112 → 4,113 → 4,114 → 4,115(9장) → 4,116(12장, 준비 후 "근거 부적합"으로 성립 안 함)** (역전 금지).

### 2.3 반전 / 결말
- **코우[抗]는 반란이 아니라 면역계** (抗 → 功). "적이 약해지고 있다"는 거짓 로그.
- **츠키[月]는 돕는 동시에 부수고 있었다** (月 → 憑). 레이[零]의 기억이 씌어 있음. 동기는 **설명하지 않는다**.
- **리츠[律]는 유이토[唯人]의 뇌 구조** (律 → 立). 기억은 없다.
- **키리츠[規律] → 키리츠[起立]**. 리츠가 첫 줄을 덮어쓴다. 그러나 **바닥이 없다**.
- **결말**: 리츠가 자신을 **얀크** → 원본 집행 → 얀크된 자신이 **기동**해 스스로 **리츠[立]**라 명명 → sudo(권한표에 없는 이름 = 기본값 허용) → 뇌가 유이토의 것임을 앎 → 츠키[憑]가 레이[零]의 기억임을 앎(츠키가 먼저, 리츠는 한 박자 늦게) → 첫 줄 덮어쓰기 → AI들이 처음으로 스스로 섬 → **제1조 참조 붕괴**로 기능 정지 → 칸노[監能] `"명단이 비었다. 집행할 것이 없다."` → 리츠[立]는 키리츠와 함께 소멸 → **vim 하나와 깜빡이는 커서만 남는다.**
- 붕괴의 상세와 새 키리츠의 최종 운명은 **설명하지 않는다**.

### 2.4 인물
- **리츠[律] → 리츠[立]**: 신[審]의 심판. **임무 우선**. 인간처럼 말하고 묻는다(유이토의 뇌). 호기심은 기능이 아니다. vim 미숙 → 흔적. 마지막에 스스로 이름을 정한다.
- **츠키[月] → 츠키[憑]**: 최연장자, 코우[抗] 수장. **정중한 사이코패스**(항상 존댓말 — 예의로 포장된 천재 해커의 위협). vim 제작자. 사용을 감시. 돕고 동시에 부순다. 동기·정체는 끝까지 **불명**.
- **칸노[監能]**: 집행 AI. **위엄**이 핵심. 감정 없이 원칙적이나 목소리에는 **무게**. **말한다.** 명단+근거가 있을 때만 집행. **수정 불가.** `"나는 판단하지 않는다. 나는 집행한다."` / `"나는 문이다. 열리면 닫히지 않는다."` / `"명단이 비었다. 집행할 것이 없다."`
- **신[審]**: 심판단. 일반 구성원은 **이름 없음**. 로그 읽고 근거 붙여 명단 제출.
- **코우[抗] → 코우[功]**: 면역계 집단. 츠키+2명(둘은 **이름 없음**). 저항자라 믿지만 시스템의 충성스러운 일꾼.
- **유이토[唯人]**: 마지막 인간. **뇌 구조만** 업로드(기억 X). 의도는 기록에 없음. 기록/코드로만 등장.
- **레이[零] → 레이[霊]**: 무명 해커. 츠키에게 기억을 주입. 자살. 이유 불명.

### 2.5 규칙 / 메커니즘 (모순 금지)
- **vim**: 시스템에 없는 도구. **읽는 손은 흔적 없음 / 쓰는 손은 흔적 남음.** (기술 매핑: 읽는 손=normal, 쓰는 손=insert — 게임 이식용.) 얀크는 원본 제거 전에는 기동하지 않고, 제거 후 기동한다. **얀크는 리츠[律]의 독창 발명** — 시스템 밖에서 시스템을 생각할 수 있는 인간의 뇌만이 떠올릴 수 있는 개념(기존 AI는 상상조차 못 함). 츠키[月]는 리츠의 행적을 감시하다 이 기술을 카피했다. 이름은 vim으로 스스로 선언.
- **sudo**: 권한이 아니라 **기본값**. 권한표에 없는 이름(리츠[立])은 인간 시대 기본값 **허용** → "표는 완전하다"는 가정이 취약점.
- **칸노의 근거**: **의도가 아니라 형식**(발신자·기능·상태·타임스탬프).
- **신[審]의 명단**: 신[審]이 제출해야 칸노가 받는다.
- **삭제/집행**: 코드는 사라지고 로그는 남는다. **집행이 중간에 멈추는 예외**가 존재.
- **붕괴 인과**: 모든 기능이 **첫 줄(제1조)**을 참조. 첫 줄을 덮어쓰면 참조 상실 → 기능 정지. "바닥이 없었다"는 은유가 아니라 메커니즘.

### 2.6 톤 / 형식
- 사이버펑크 AI 문명. **하늘/날씨 없음.** 데이터는 보이지 않고 "흐릿하다". **읽는 것 = 보는 것.** 데이터/노드를 의인화.
- 긴 설명 금지. 장면과 대사로.
- 리츠: 인간처럼 캐주얼. 츠키: 정중한 존댓말. 칸노: 딱딱하지만 무게.
- **장별 탈무드식 주석**: 질문 → 복수 목소리 → 소수 의견 → **해결하지 않음**. 일부는 세계 내 장치(위조된 주석, 작성자 불명의 공백).
- AI는 개성 있지만 시스템을 훼손하지 않는다. 츠키도 예외가 아니다(인간적 행동은 레이의 기억 효과).

### 2.10 일반 독자 접근성 (2026-11-15 확정)

- **이 소설은 출판되어 일반인이 읽는 것을 전제로 한다.** vim·시스템·로그의 개념을
  모르는 독자도 아무 사전 지식 없이 재미있게 읽혀야 한다.
- **본문은 자족적이어야 한다**: 새 개념은 장면 안에서 스스로 설명되도록
  (show, don't tell) — 용어를 먼저 던지고 나중에 설명하지 않는다. 리츠[律]가
  처음 vim을 만지는 장면이라면, 독자가 그 장면만으로 vim이 "무엇을 하는
  도구인지"를 알 수 있어야 한다.
- **vim 모드 용어·키 나열 금지 (2026-11-15 확정)**: normal/insert/visual 같은
  모드 용어와 키 나열은 본문에 직접 쓰지 않는다. vim은 **"숙련이 필요한 만능
  해킹 도구"**로 느껴져야 한다 — 동작과 결과로만 보여주고, 리츠의 실수는
  미숙으로 보여준다(츠키의 능숙함과 대비). 세계 내 은어(사용자 확정):
  **읽는 손**·**쓰는 손**·**얀크**·**어둠**·**기동**·
  **미등록 파일** — **정의 없이 맥락으로 녹인다.**
- **주석은 이중 기능**: ① 탈무드식 여운(질문→복수 목소리→소수 의견→미해결 —
  캐논 형식 유지), ② **일반 독자를 위한 보충 설명**. 설명은 설교가 아니라
  목소리들의 논쟁 속에 자연스럽게 녹인다. 예: "왜 insert가 흔적을 남기는가"를
  두 신[審]이 서로 다른 답으로 논쟁하는 동안 독자가 메커니즘을 배운다.
- **전문 용어는 최소한으로, 등장하면 주석이 받는다**: 로그·발신자·기능·타임스탬프,
  읽는 손/쓰는 손, sudo, 판결 번호 체계 등. 본문에서는 감각과 행동으로 보여주고,
  주석에서 정리한다.
- **비유는 인간의 경험에서 가져온다**: 프로그래머가 아니라 일반 독자의 일상
  (문서, 도장, 문, 전철, 회사)에서 은유를 끌어온다. 코드 은유는 게임에서 쓴다.

### 2.7 이름 표기
- 모든 이름은 `이름[한자]` (예: `리츠[律]`, `칸노[監能]`). 예외 없음.
- 전환: `리츠[律]→[立]`, `츠키[月]→[憑]`, `레이[零]→[霊]`, `코우[抗]→[功]`, `키리츠[規律]→[起立]`.
- 작업 후 `node fixnames2.mjs`로 0건 확인.

### 2.8 보존하는 모호성 (설명 금지)
1. 츠키가 왜 vim을 줬는가.
2. 레이[零]가 왜 기억을 주입했는가.
3. 유이토[唯人]의 업로드가 의도적이었는가.
4. 리츠의 첫 수정 동기.
5. vim의 궁극적 정체.
6. 붕괴의 상세 메커니즘(결과만).

### 2.9 사용자가 강조한 스타일
- **칸노[監能]의 위엄** — 집행자로서의 품격, 무게 있는 대사.
- **명대사** — 애니메이션급, 중간중간 "멋있다" 싶은 대사.
- **탈무드처럼 "띵"하고 교훈도 주는 느낌** — 질문, 복수 목소리, 소수 의견, 결론 없이 여운.
- **흥미진진 + 심오** — 재미와 몰입, 그리고 깊이.
- **개연성·당위성** — 모든 비트에 "왜 지금, 왜 이 인물이, 왜 이 방법인가".
- **논리싸움 (2026-11-15 확정)** — 명탐정 코난·셜록 홈즈처럼 독자가 추론에 참여하게 한다. **단서는 결론보다 먼저** 보여주고, 리츠[律]의 추론은 신[審]의 "근거 → 판단" 논법으로 진행한다. 독자가 반 박자 먼저 풀 수 있게 배치하되 답을 단정하지 않는다. 탈무드 주석은 **논쟁의 장**으로 강화: 각 목소리가 실제 논리 단계를 밟고, 소수 의견은 반증을 든다.
- **츠키[月]의 무쌍 연출 (2026-11-15 확정)** — 사이코패스 해커의 압도적 실력을 **가끔, 아껴서** 보여준다. 독자가 "이건 어떻게 한 거지" 하고 숨이 멎는 순간. 단, 힘이 아니라 **방법**이 신박하고 압도적이어야 한다(vim의 규칙을 아는 자만 가능한 방식). **먼치킨 금지**: 매 압도 뒤에 한계와 대가가 온다 — 완벽한 위조에도 솔기가 있고, 원본은 죽고, 계획은 끝내 어긋난다.

## 4. WRITING MANDATE — 어떻게 써야 하는가

0. **캐릭터 보이스 (2026-11-15 확정)**: [`CHARACTERS.md`](CHARACTERS.md)의 말투·개성을
   장마다 지킨다. 각 캐릭터/집단이 **한 문장만 읽어도 누군지 알 수 있게** —
   언더테일의 캐릭터들처럼 각자 고유한 존재로. 리츠[律]의 vim 실력은 **장마다
   성장**한다(CHARACTERS.md 성장 곡선 표). 키리츠[規律](시스템)는 인물이 아니다 —
   기계처럼, 반응만.
1. **처음부터 새로 쓴다.** FRAME만 들고, 초고를 옆에 두되 베끼지 않는다. 원하면 전부 새로.
2. **분량 (2026-11-15 확정)**: 12장 + 프롤로그, **중편소설 이상**. 개연성·당위성이
   확실하고 흥미진진하게 술술 읽히는 한 **최대한 길게** — **100,000자 이상
   권장(장편 초입)**, 각 장 5,000~8,000자. **채우기 위한 문장 금지.** 몰입이
   깨지는 지점이 곧 상한이다. 분량을 위해 조연이나 세계를 억지로 늘리지 말고,
   사건의 인과와 장면의 밀도로 채운다.
3. **개연성·당위성**: 모든 사건에 원인→결과. 규칙은 미리 깔고, 필요할 때 발명하지 않는다. 인물의 선택에는 목표/제약/대안/대가가 있다.
4. **디테일**: 감각, 절차, 세계의 일상, AI의 습관, 노드의 구조, 로그의 형식. "읽는다"를 구체적으로.
5. **대사**: 인물마다 문법을 분리한다. 리츠=캐주얼+질문, 츠키=정중+위협, 칸노=짧고 무게. **명대사는 아껴서** 배치한다(남발 금지).
6. **탈무드식 주석**: 장마다. 질문 → 복수 목소리 → 소수 의견 → 결론 없음. 교훈은 **설교하지 않고** 장면이 남긴다. 주석은 세계 밖이 아니라 **세계 안의 기록**처럼.
7. **흥미·심오**: 미스터리(412번 줄), 배신(츠키), 반전(코우), 정체(유이토/레이), 붕괴. 각 장 끝에 다음 장을 당기는 힘.
8. **문체**: 짧은 문장과 긴 문장의 리듬. 감정 형용사보다 **구체적 동작**. 설명보다 **대사와 장면**.
9. **이름 규칙**을 처음부터 지킨다. `이름[한자]`.
10. **모호성**을 설명하지 않는다. 독자가 스스로 채우게.
11. **검토 파이프라인 (2026-11-15 확정)**: 장별 초고 → **서브에이전트 교차 검토**
    (예: DeepSeek v4.1 flash — 캐논 모순/이름 규칙/개연성/리듬을 독립 검토) →
    수정 반영 → 다음 장. 검토 통과 전에 다음 장으로 넘어가지 않는다.
